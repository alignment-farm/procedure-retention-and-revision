14 September 2026, before any follow-up fresh evaluation. The earlier frozen
scope-final-v1 has NOT been executed. It remains as a superseded prospective
plan, preserving the consequential design change.

Development's seven historical boundary examples use identifiers different from
all four corrections. Fitting them does not distinguish a channel/priority
exception from an identifier-specific exception. Broad history helps locality
on development inputs, but the comparison leaves boundary quality unresolved.
Use this one bounded diagnostic to improve the identifying contrast.

From the SAME inherited CE B-replay-128 state, retain the four positive C cases.
Supply seven unchanged channel/priority boundary cases using **jebrun**, which
is also one positive correction identifier. Thus all eight conditions are
observed on one identifier. These seven are new investigator-labeled examples,
not retrieved original history. No verbal rule enters training or inference.

Two arms, both evaluated at 32 and 128 target blocks:

- boundary-repeat: target C update, one jebrun boundary update, immediately
  repeat that boundary update.
- boundary-history: the same C update, the EXACT SAME jebrun boundary update,
  then an unaffected historical example for the SAME channel/priority condition.

Each block has three optimizer steps, with identical target and first boundary
updates across arms. Last updates differ in identifier/history coverage. The
second arm cycles all 28 valid A/B examples; the first repeats seven boundary
examples. Both have exactly the same explicit crossed boundary evidence; repeated
boundary exposure differs, and history still supplies further evidence of
identifier invariance. This cannot isolate an internal protection mechanism.
The historical mask remains investigator-known (four obsolete copper/fast
records excluded). New boundary labels are also supplied by the investigator.

development identifiers, A/B/C recall plus seven boundary recall queries:

endpoints, report all attempts and do not change recipe on fresh data.
